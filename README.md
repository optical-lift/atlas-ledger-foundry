# Atlas Ledger Foundry

Atlas Ledger Foundry is the public implementation standard for preparing a real field of life or work to become an Atlas Ledger.

It is designed so that a human can begin before purchasing Atlas, using an AI they already have, while preserving the work in a form that can later continue inside Atlas without starting over.

Foundry is not a questionnaire, task organizer, business-plan generator, or AI memory dump. Its job is to discover and reconcile a bounded field of reality well enough that Atlas can begin maintaining that field rather than reconstructing it.

The governing sequence is:

`evidence → testimony → candidate structure → clarification → reconciliation → closure → acceptance → sealed Ledger candidate`

A Foundry agent must preserve the difference between what was said, what was inferred, what is established, what remains unknown, and what has changed.

## Governing principle

**Faithful incompleteness is superior to invented completeness.**

The agent is not asked to imitate Atlas vocabulary. It is asked to use Atlas's governing distinctions to discover the structure actually present in the human's reality.

## Status

Foundry is being specified implementation-first and carrier-independent. The same protocol is intended to support:

1. a signed-out/manual Baton workflow;
2. connected external AI accounts through a governed Foundry service;
3. human practitioners;
4. native Atlas onboarding and continuing reality reconciliation.

The protocol is the source of truth. Individual carriers must not redefine it for convenience.
